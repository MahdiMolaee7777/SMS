About the project

A university machine-learning assignment: build a working classifier for unwanted SMS messages and a web interface that shows its result honestly.

Objective

The goal is to build a model that receives the text of an SMS message and decides whether the message is normal (Ham) or Spam - for example unwanted advertising, fraudulent offers or messages carrying suspicious links.

Three algorithms are trained on the same features and compared with accuracy, precision, recall and F1-score. A small web application then lets a user type a message and see the classification produced by the trained model.

Dataset

The project uses the SMS Spam Collection corpus supplied with the assignment: one message per line, a tab between the label (ham / spam) and the raw message text. It is a real, human-labelled collection of English messages - mostly conversational (Ham) and promotional or fraudulent (Spam).

TF-IDF in one page

A classifier cannot read words, so every message is converted into numbers. TF-IDF does this in two steps:

  • TF (term frequency): how often a word (or word pair) appears in this message. Frequent words describe the message.
  • IDF (inverse document frequency): words that appear in almost every message ("you", "to") carry little information, so their weight is reduced. Rare words carry more.
  • The result is one weight per term per message: the message becomes a vector with thousands of dimensions - most of them zero.
  • Unigrams and bigrams are used here, so the model sees both single words and short phrases such as "free entry" or "call now".

The vectorizer is fitted on the training split only. Fitting it on the whole dataset would leak information from the test messages into the model and inflate the reported scores.

Limitations and responsible use

This is an educational spam classifier. It makes mistakes: legitimate messages can be flagged as spam, and well-written spam can pass through.

  • The corpus comes from 2011 and is dominated by UK English, so modern wording, currencies and phone formats are underrepresented.
  • Only the message text is analysed. Sender reputation, sending patterns and link reputation are not available.
  • Reported probabilities are model estimates; the SVM value is a decision margin, not a probability. None of them is proof that a message is safe or fraudulent.
  • Do not use the output as legal, financial or security advice, and do not delete or block messages based on this model alone.
